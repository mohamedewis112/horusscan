# Horus Security Lab — current workbench

This branch reuses the existing HorusScan repository and Vercel web project. **No ARTEX executor has been deployed and no destructive test has occurred.**

## Working capabilities

- Browser-only, deterministic, heuristic review of manually pasted **HTTP response** headers. The browser does not fetch the target or send the pasted headers to the server.
- Export a JSON report containing derived findings, not pasted raw headers.
- A real Next.js server-side API at \`POST /api/lab/ai-review\`. It can review a list of derived findings with Groq GPT-OSS 120B or an OpenRouter open-weight model.
- The API is disabled until credentials have been set in the **existing \`horusscan-web\` Vercel project**. No credentials are embedded in the browser bundle. There are no tools or shell execution exposed to the model.

## Set the following existing project's Preview environment variables directly in Vercel

\`\`\`dotenv
LAB_OPERATOR_TOKEN=<a long random 32+ character secret generated by the operator>
GROQ_API_KEY=<your Groq API key>
# OR
OPENROUTER_API_KEY=<your OpenRouter API key>
OPENROUTER_MODEL_ID=openai/gpt-oss-20b:free
\`\`\`

Use at least one provider key. Configure the variables for Preview and redeploy the Preview. **Never paste secrets into this repository or tickets.** The UI prompts for a personal operator token which is transmitted only to the first-party API for timing-safe comparison, kept only in in-memory component state, and never logged or stored by the application. Provider quotas and model availability vary.
